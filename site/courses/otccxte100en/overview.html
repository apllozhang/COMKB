1. 结构 (Structural)

类型

实操手册（厂商培训教材：概念讲义幻灯片 + 分步实验 How-To；围绕 OXE 内置呼叫中心（CCD）+ CCS 班长台的双控制台交付闭环）

一句话主旨

在 OXE 上把一个呼叫中心从零跑通：先建 CCD 矩阵（pilot/队列/处理组）并装好 CCS 班长台，再配路由与分配规则、座席与班长，然后用 20 个实验逐域加能力——语音指南（话机录音/.wav 导入/欢迎指南/多语言/排队位置播报）、座席班长特性（监听强插/通用转发/多线/事务码）、EWT 交互排队、实时监控告警、CCD 直接呼叫、Excel 统计、紧急关闭、统计型 pilot 与日历。

骨架 (主要论点及其关系)

  1. 培训实验环境（RLAB POD 五实例 + ITSP1 公网 SIP 模拟器：账号、号码变换、DID 翻译、RDP 音频串联）
  2. CCD 矩阵模型（pilot→路由→队列→分配→处理组五级模型；pilot 三态、队列三类型四状态、PG 五类型与兼容表；优先级 0-9 与 EWT/LIT 平局规则；Rainbow 座席三登录形态）
  3. 基础交付闭环（建 ACD 前缀/PG/队列/pilot → 装 CCS 并声明 OXE → 建路由与分配规则并激活 → 建 ACD 话机/座席/班长并登录 → 收尾 POD 的 SIP/DID 参数 → 开通本地 ABC-F 内呼链路）
  4. CCS 对象调优（pilot 的 wrap-up/pause/服务水平目标，PG 八选项逐项行为测试，队列饱和与溢出参数）
  5. 语音指南域（静态/动态体系、板卡与编码 → 话机录音排矩阵 → .wav 转换导入 → 欢迎指南 → 多语言 → 518 排队位置播报）
  6. 座席班长特性域（退出类型、监听/强插/永久监控、通用转发四种激活、PG 关闭、多线座席、事务码）
  7. 排队增值域（EWT 表 + IAA/CCIVR 交互排队 + 位置指南）
  8. 运营监控域（Navigator 实时视图定制、中继 CSTA 监控、S.L./MSP 统计、三级告警与阈值）
  9. 直连与统计域（CCD 直接呼叫与私人号码、Excel 统计体系与预编译报表）
  10. 应急与营销域（紧急关闭、统计型 pilot 与 Call Tag、双日历体系）

论点之间的关系: 层层递进为主——1 是地基，2 是全书的智力骨架（一切操作都回到矩阵模型），3 是最小可用呼叫中心（无它后续全部空转），4-10 是并列的能力域：5/6/7 面向呼叫者与座席体验，8/9 面向运营管理，10 面向应急与业务分账；每个能力域都遵循"讲义先行、实验落地、Navigator 验证"的三段节奏。

作者要解决的核心问题

让售后/交付工程师独立完成"OXE 内置呼叫中心"的入门级交付与运维：从建矩阵、装 CCS、配规则与人员，到语音指南、座席体验、监控统计、应急处置的全套动手能力，并能用 OXE Web Admin、CCsupervision、命令行三个入口协同排障。

2. 解释 (Interpretive)

关键术语 (作者本人的用法)

术语 作者的定义 和常识用法的差异
CCD OXE 内置的呼叫分配软件与对象体系（CCD matrix/objects/users），OTCC Standard 的核心引擎 书中未展开三字母全称；不等于泛指的"呼叫中心"，特指这套分配矩阵
Pilot 来话首先到达的虚拟被叫号，三态（Open/General Forwarding/Blocked），经路由规则导向队列 不是"导航员"，也非 IVR 菜单；Blocked 是"下游无资源"的自动态
Waiting Queue 呼叫停车常：三类型（Normal/Intelligent Overflow/Redirection），FIFO，≤30 pilot 共享、服务 ≤50 PG 不是简单的"排队"；溢出/重定向类型本身携带处理逻辑
Processing Group 资源组：Agent/Forward/Voice Guide/Rerouting/IVR 五类型，兼容表约束与队列的连接 "组"不一定是人——语音指南、前转、改道都是组
Routing rule / Distribution rule 路由规则连 pilot↔队列（≤30/pilot），分配规则连队列↔PG（≤10 全局） 两级规则都要手动激活；方向默认全关——"连好线"≠"能通话"
EWT 预期等待时间 = 平均等待×(队内呼叫数+1)，按队列 TSP 滚动计算 同时是路由平局依据、饱和判据、播报分档依据三重角色
Wrap-up / Pause 话后处理态（自动挂 pilot/手动挂 PG）与两通 CCD 呼叫间的 union break（可接私人电话） pause ≠ 不可用；wrap-up 中做操作即取消（Queue info 除外）
ACD prefix 话机功能码前缀（实验 12）：+1 退出/+2 wrap-up/+3 呼班长/+5 登出/+6 登入/+91/+92 模拟话机的全部 CCD 操作入口；须在 COS 启用
CCS (CCsupervision) 班长/管理台（Windows 应用）：规则、座席、实时、统计、紧急关闭 无权创建 CCD 底层对象——与 OXE Web Admin 的分工是硬边界
ccs.ini CCS 启动读取的配置文件（站名、id_terminal 0..127、token 类型、PABX 地址） 多数设置走 CUSTOMIZE 窗口；ShowStatisticWithData 是必须手改的例外
Statistic Pilot 统计型 pilot：对外业务号，先播问候再转唯一关联的路由 pilot，可挂 Call Tag 与路由 pilot 是两层；问候只在路由 pilot"按规则"关闭/阻塞时播
CCD Direct Call 把打座席号的外线来话纳入 CCD 待遇的机制，靠 direct call pilot + 私人号码实现 私人号登录时自动前转、登出自动取消；本地混合链路不能承载它
Emergency Closure 一键关闭 pilot 列表（≤50 列×600 pilot），来话优先转关闭地址/指南 统计上算"通用转发态来话"；未配地址时向他转移被拒
Voice guide 静态（打包 Flash）/动态（录制 RAM）语音资源；3 位指南号放矩阵、4 位消息号供录制 518/538 与 3226-4217 是预置资源，不可自造同号
Calendar (pilot/distribution) 双日历体系：pilot 10 切换/日、分配 20 切换/日、50 个特殊日覆盖周历 活动时间片上的修改延迟到下一切换点生效
MSP / TSP / SOP 监控采样周期(5-60 分)/话务采样周期(每队列)/班长观察周期(默认 15 分) 三个周期各管一摊，实验里都取 15 分钟档但语义不同

核心命题 (用自己的话)

  1. OTCC Standard 是 OXE 的内置能力（不是外挂服务器），可选件只有 CCS/CCA/ACR/Soft Panel——交付的主战场就是 OXE Web Admin + CCS 两个图形台加命令行。
  2. 一切呼叫流服从五级矩阵：pilot→路由→队列→分配→PG；配置的本质是在这五级上"连方向、定优先级、给默认行为"。
  3. 优先级体系统一为 0-9（0 最高），但三类平局规则不同：路由看 EWT、资源选择看 LIT、呼叫选择看真实等待时间。
  4. 默认值是"全关"：分配规则默认停用（OXE 侧激活）、所有方向默认关闭、末座席退出可被禁——"配好了不通"先查激活与方向。
  5. 座席体验由三个计时器与一组状态构成：wrap-up（自动挂 pilot、手动挂 PG）、pause（可接私人电话）、退出（9 种类型供统计）；状态时序是排障的共同语言。
  6. 语音指南是呼叫中心的"皮肉"：编号法（3 位指南+4 位消息）、两条录入路径（话机 401/580 与 .wav 转换+SFTP）、四种落位（演示/停车/阻塞/通用转发）构成完整闭环。
  7. EWT 与 518 位置播报是排队体验的两把尺子：前者分档播等待预估（受 TSP 滞后），后者按 1-50 逐个、51-100 步进 5 播位次（上限 100，语言缺失有回退链）。
  8. 监控三层：Navigator 3 秒快照看状态、MSP/SOP 统计看质量（smiley 三色 = 阈值/0.8 阈值）、Alarms/Alerts/Indications 三级事件（各存 100 条）看异常。
  9. CCD 直接呼叫把"座席直通号"纳入呼叫中心统计：direct call pilot 提供溢出与计时、私人号随登录自动前转、座席外呼经 Outgoing ACD Call 计入统计——呼叫性质按座席状态逐格判定。
  10. 统计是文件驱动的：OXE 午夜生成 5 类临时文件、合并为 hr/dy/ev 三类（保留 5 周/12 个月），CCS Excel 报表只认 Business 码；对象数、粒度、行偏移（96 行/天、132 行第二对象）都是可核算的参数。
  11. 应急与营销靠三个机制：紧急关闭（50 列×600 pilot、转移受限）、统计型 pilot（3000 个、Call Tag 32 字符、问候依赖"按规则"关闭）、双日历（10/20 切换每日、50 特殊日、切换点语义）。
  12. Rainbow 只以"座席形态"进入本书：三不限制（不入 multiset、不关联 Rainbow 用户、DECT 不支持）+ 三种登录（office phone/REX/computer+WebRTC），远程座席免 VPN/SBC。

论证链

教材以"模型讲义 → 双控制台分步实验 → 行为验证"推进：每个 How-To 都有 Implementation（业务目标）+ 步骤（菜单路径 + 字段值）+ 验证（Navigator 状态、话机显示、听感脚本、acdsup 输出）；参数类命题（优先级、EWT、计时器、容量上限）先在讲义给定义与数值域，再在实验里用对照测试（如 PG 八选项逐项开/关对比行为）证明。行为闭环替代理论论证，数值逐格可复现。

3. 批判 (Critical) ★

作者的时代局限

  • 基于 OXE R10.16 时代界面与法国目标库默认值（ABC Local Call Allowed、401/580 前缀、538/518 预置、"法语库默认关"的参数等），跨目标库/跨版本交付需逐一核对。
  • CCS 为 Windows 桌面应用（Excel 报表、TEMP.xls、Print 输出），云化/网页化演进完全不在视野内。

作者的立场盲点

  • 全书默认实验环境：明文口令（Superuser2580*/alcatel/letacla1/0000）遍布正文，生产安全基线（口令轮换、账号收敛）只有一处"强制改密"示意。
  • 书内自相矛盾多处未修订：p153 口令 mtcl/mtcl、建队列表格三步同值、acdsup/acdsetup 混用、语言索引英文时而 #1 时而 #2、统计目录两种写法、"四条消息"实际三条、Agent2 串写 31502 等——照抄会踩坑。
  • 容量与话务建模缺位：TSP/EWT 只给公式与"逐步调参"，没有给出话务量→队列数→座席数的规划方法；多站点（Multisite CCS）只出现在 ccs.ini 注释里。

未被证明的假设

  • 假设读者持有 RLAB 环境与预置 OXE 数据库（许可已恢复、指南已下载、SIP 中继已建）——生产从零交付的差距（中继申请、编号计划、COS 规划）未覆盖。
  • 假设客户场景是单站点、法/英双语、20 人以内座席；紧急关闭、统计 pilot 等机制在大规模下的行为未验证。
  • 假设 Rainbow/WebRTC 侧环境现成（网关、订阅），Rainbow 座席一节只有架构图没有落地步骤。

最强反对意见

"这本 Starter 教的是把一个单点呼叫中心在实验室跑通，不是呼叫中心交付方法论"——编号计划、COS 体系设计、中继与话务工程、CCIVR/ACR/CCA 全渠道、宏与多站点都只是点名或指向 OTCC901 进阶教材与 Feature list。因此每个能力的 Boundary 必须标注"实验口径/单站点/R10.16"，并显式指向 OTCC901、Feature list OmniTouch CC Standard Edition、目标库文档三份外部依据作为生产化支撑。

以上批判会直接成为下游 skill 的 Boundary (B) 字段来源
