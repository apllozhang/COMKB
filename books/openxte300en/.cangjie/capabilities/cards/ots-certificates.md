# 证书部署三路线（security OFF / 自签 / 外部 CA 与 Windows CA 全流程）

## R — 原文依据

> "Certificates for the server can be generated from different ways Certificate, generated by a certification authority server ... Self-signed certificate ... "Generic" certificate and CTL signed by a "generic" device Choice done during installation (security off)"（p400）
> "BEWARE: THIS CHOICE IS NOT RECOMMENDED BY ALCATEL-LUCENT ENTERPRISE, AS IT IMPLIES INCREASED RISKS OF TOLL FRAUD, AND UNAUTHORIZED USE OF THE SERVICES OR FUNCTIONALITIES ON THE SYSTEM"（p103）
> "Type Select the certificate type: Internal -> autogenerated Signature algorithm Select the algorithm: SHA-2 (SHA256)"（p427）
> "Once the certificate imported, don't forget to deploy it in order to be used by the system"（p423）

出处：OPENXTE300EN p397-429。

## I — 自述

证书三档位：

| 路线 | 触发场景 | 要点 |
|---|---|---|
| security OFF | 安装时可选的通用证书与 CTL | 全球所有 OT 服务器同款；官方点名不推荐（盗打与越权风险） |
| 自签 Internal | 向导选 ON+Internal | SHA256（SHA-1 自 R2.2 弃用）；Local PKI 可补主体信息（默认有效期 7300 天）；换证后必须用 808x 话机重签 CTL |
| 外部 CA | 远程接入必需、安全最优 | 根 CA 先导入 Server CTL 页；CSR 可在 WebAdmin 生成或 CA 侧做；按 CSR 来源导 PKCS7（无口令）或 PKCS12（带 passphrase） |

两条流程铁律：导入（Import）与部署（Deploy）是两步，漏 Deploy 证书不生效；Deploy 后 WebAdmin 报"Impossible to retrieve data"并断会话属预期（https 证书刚换），重开会话即可。

Windows CA 实操路径：浏览器开 CertSrv 申请页，高级申请以 base64 提交 CSR，模板选 Web Server，下载 Base 64 证书链后导入。远程接入两案：泛域名证书一张撒三处（OT/OTSBC/反向代理），或每服务器各签；客户端信任根须分发到 PC。

## A1 — 书中案例

**自签证书实验**（p424-429）：

1. 查现状：Certificate 页看当前证书类型与签名算法。
2. 装机选过 security off 的站点当前显示通用证书（Display Name 为星号）。
3. Change server certificate 选 Internal 加 SHA256。
4. 弹出 CTL 须重签的警告时确认 Yes。
5. Local PKI 页补齐国家、公司等主体信息。
6. 用 808x 话机按 USB 流程重签 CTL。
7. Deploy 新证书；会话断开重开即可。

**Windows CA 外部证书实验**（p412-423）：

1. 取根 CA：浏览器打开客户 CA 的 CertSrv 页面。
2. 导入根证书到 OT 的 Server CTL 页。
3. 核 PC 客户端证书存储已有该根，缺则安装。
4. 需要时在 WebAdmin 生成 CSR（SHA256）。
5. CertSrv 高级申请以 base64 提交 CSR，模板选 Web Server。
6. 下载 Base 64 证书链并按格式导入（PKCS7 或 PKCS12）。
7. 选中证书点 Deploy，重开会话验证新证书生效。

## A2 — 未来触发

使用情境：浏览器总提示证书不受信任；要上远程接入（SBC/反向代理）；security off 站点整改；换证书后客户端连不上。

语言信号：证书 / certificate / 自签 / self-signed / CA / CSR / PKCS7 / PKCS12 / passphrase / CTL / SHA256 / security off / Deploy / CertSrv / 泛域名 / 信任根。

与相邻能力区分：客户端信任根分发与客户端连通找客户端能力；SBC 与反向代理安装在书外（TC2257/TC2639）；向导内证书档位决策属初始化向导能力。

## E — 可执行步骤

输入契约：证书路线决策（自签或外部 CA）；CA 基础设施与模板权限；808x 话机与 USB（自签 CTL 重签用）；客户端信任根分发计划。

1. 定路线并备料（根证书、CSR、模板权限）。完成标准：材料齐
2. 导入根证书到 Server CTL 页。完成标准：CTL 列表含根
3. 签发并导入服务器证书（格式按 CSR 来源选）。完成标准：证书入列
4. Deploy 并核 https 生效。完成标准：浏览器显示新证书
5. 自签另做 CTL 重签；外部 CA 另分发客户端信任根。完成标准：终端与客户端无信任告警

判停点：

- 导入后"没生效" → 漏了 Deploy（导入与部署是两步）
- Deploy 后报 Impossible to retrieve data → 预期现象，重开会话，不要回滚
- 自签后 808x 话机信任异常 → CTL 没重签，补 USB 流程
- 生产站点还在 security off → 官方不推荐（盗打风险），列入整改计划
- 证书链不全 → 根 CA 没导入 Server CTL 页或客户端没装根

输出契约：生效的服务器证书（路线/算法/有效期）+ CTL 重签与信任根分发记录。

## B — 边界

- 实验口径：CA 服务器为 eco.company.com 的 CertSrv（R-Lab 亦可从 NAS 取根证书）——生产用客户自己的 CA。
- SHA-1 自 R2.2 弃用，一律选 SHA256（p426）。
- 通用证书全球同款，风险为盗打与服务越权（p103/p426），已用 OFF 的站点要整改。
- 证书变更（主机名/域名）后 OTMS 需重启，并按 TC2149 收尾（TC2149 2.4）。
- SBC/RP 的安装与 VPN-less 会议地址属 TC2257/TC2639 与专项培训（书外）。
