## 1. 结构 (Structural)

在 OXO Connect 上从零规划、配置、验证并运营一套 ACD 呼叫中心（含话务分配引擎、坐席/班长/统计三件套与多秘书扩展）。

### 骨架 (主要论点及其关系)

1. **实验环境**（RLAB 远程实验室 + SIP 运营商模拟器：POD 规划、MicroSIP、ITSP1 号码规则）

## 2. 解释 (Interpretive)

### 关键术语 (作者本人的用法)

| 术语 | 作者的定义 | 和常识用法的差异 |
|---|---|---|
| ACD | 集成在 OXO Connect 内的自动呼叫分配服务（非独立软件），经 CSTA 链接驱动寻线组与虚拟终端 | 不是通用呼叫中心平台概念，而是特指 OXO 内置引擎及其许可体系 |
| ACD 端口 (ACD ports) | 每个 ACD 组的呼叫接入资源（最多 16 个），全忙即进入劝漏第二形态 | 常被误解为"坐席数"，实际是并发接入通道数 |
| 劝漏 (Dissuasion) | 队列满或端口全忙时对呼入的劝退处理（播语音后释放/转号码/进组邮箱） | 不是"呼叫拦截"，是三种可选出口的状态 |
| 呼叫特征化 (Call characterization) | 按 CLI（主叫）与 DDI（被叫）把呼入匹配到 ACD 组的机制，三级优先比较 | 类似智能路由，但匹配方向有规定：CLI 从左向右、DDI 从右向左 |
| 搜索模式 (Search mode) | 组内选坐席的算法：Fixed（固定优先级）/ Rotating（轮转）/ Longest idle（最久空闲） | 与坐席跨组优先级（rank）是两个正交概念 |
| Free seating | 坐席用前缀/按键在任意终端登录 ACD 会话（terminal↔agent 动态绑定） | 不是"移动分机"，是坐席与话机的临时关联 |
| 状态前缀 501-504 | On duty / Off duty / Clerical work / Temporary absence 四态的拨号代码 | 教材四态是固定集，Supervisor 应用里细化为九种子状态 |
| ACDAutoLog | 系统编号，控制登录后默认状态：01=on duty，00=off duty | 隐藏寻址项，非常规菜单选项 |
| Multi-Secretary | 基于 ACD 引擎的"多经理共享秘书"模式（需许可），显示 [组名][主叫][等待时长] | 是 ACD 的预设形态，非独立产品 |
| ACD Admin 密码 | Supervisor/Statistics 应用的专用管理密码（区别于 installer 密码） | 教材实验值 Acdc1064，仅限实验环境 |
| ITSP1 / SIP Simulator | RLAB 公网模拟器：模拟国内外长途与紧急号码，账号规则含 POD 号 PN | 生产环境的真实 SIP 中继不在本书范围 |
| Call qualification | 坐席通话后用 Types 表预定义的代码给来电分类，供统计 | 是"通话后打标签"，不是实时质检 |

### 核心命题 (用自己的话)

1. ACD 内置于 OXO Connect，开启即得，无需外置呼叫中心服务器；容量上限 32 坐席/8 组/16 端口/10000 条路由规则/统计留存 14 个月。
2. 所有呼入按"营业时间测试 → 六种场景（空闲/全忙/队满/端口全忙/全员登出/组关闭）"处理，每种场景都有语音/转接/邮箱三种出口可选。
3. 配置分两层：ACD Setup 向导一次成型（前缀、DDI、邮箱、按键 profile、坐席声明），ACD Services 菜单做精细调整（路由表、坐席参数、组参数、语音）。
4. 呼叫特征化的匹配有严格优先级：CLI+DDI 双匹配 > 仅 DDI 匹配（CLI 空白）> 仅 CLI 匹配（DDI 空白）；路由表必须从最特殊（最长号码）填到最一般。
5. 队列长度 = 值机坐席数 N × 话务因子 K（0.1-9.9），向上取整，上限 16；预计等待时间 = (队列呼叫数/值机坐席 + 1) × 平均通话时长。
6. 坐席进组靠登录（free seating）：终端 + 坐席 + 组 + 坐席名四者建立关联才进入 ACD 会话；登录后默认状态由 ACDAutoLog 控制。
7. Supervisor 与 Statistics 应用必须使用独立的 ACD Admin 密码，避免把 installer 密码暴露给最终客户。
8. Multi-Secretary 复用 ACD 引擎：把"经理 DDI"当被叫特征化、秘书组当坐席组，即可实现多经理共享秘书团。
9. 客户识别靠 DTMF 客户码：来电者输码（如 035#）触发坐席席面屏幕弹出客户资料。
10. 语音提示按固定编号（101.wav=欢迎语…107.wav=客户码提示）管理，可终端 MMC 录制或 OMC 批量上传。

### 论证链
教材以"概念讲义 → OMC 菜单路径 → 分步实验 → 验证测试"循环推进：每章先给流程图/规格，再给 OMC 精确菜单路径（OMC / …），然后让学员在 RLAB 上按场景做并自测（如"呼叫组 3 无人接听会发生什么"），以行为验证闭环替代理论论证。

## 3. 批判 (Critical) ★

### 作者的时代局限
- 基于 R6.x 界面与 RLAB 模拟器；OMC 菜单在更新版本可能重排。
- 队列/等待时间公式是线性简化模型（M/M/N 的粗化），真实话务高峰会低估等待。

### 作者的立场盲点
- 全书默认可信内网（192.168.1.x，密码明文写在教材：pbxk1064 / Acdc1064），**生产环境的安全加固、SBC 对接、公网 SIP 防护完全缺位**。
- 只讲单 OXO 站点，无组网/灾备/多站点话题。
- 许可仅罗列包名（Welcome 5 坐席/8 组 + Option），无容量规划方法论（如何从话务量反推坐席数与端口数）。

### 未被证明的假设
- 假设读者已有 OMC/IP 基础，IP 规划（192.168.1.x）直接给定不论证。
- 假设 501-504 前缀不会与客户拨号计划冲突，未给冲突排查方法。
- 假设 SIP 中继由 ITSP 模拟器替代后行为与生产一致（实际抖动/编解码/安全差异大）。

### 最强反对意见
"这本实验手册教会的是在模拟器上点菜单，不是交付呼叫中心"——若没有话务量分析与容量规划、安全基线、真实中继对接这三块，按书配完也只是实验可用。因此每个能力的 Boundary 必须标注"实验环境口径"，生产化条件（改默认密码、真实中继、话务建模）需显式提示。

> **以上批判会直接成为下游 skill 的 Boundary (B) 字段来源**
