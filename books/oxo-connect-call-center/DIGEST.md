# DIGEST — OXO Connect 呼叫中心精华长文

> 源：OXOCXTE107EN Edition 07（218 页）· 文档整理入库 · 2026-09-23
> 定位：10 分钟建立 OXO ACD 的全局认知；操作细节按需查 15 张能力卡。

## 一、这套东西是什么

OXO Connect 的呼叫中心（ACD）是**内置于话机的服务**，不是外挂软件：开许可、做配置，话机就变成有排队、有话务分配、有统计的呼叫中心。坐席用什么话机都行（模拟/DECT/IP/TDM/软电话）。许可分两档：Welcome 底包（5 坐席 8 组），加 Option 解锁坐席助手、班长台、统计。

容量天花板：32 在值坐席、8 个组、16 个 ACD 端口、每组 6 条语音、10000 条路由规则、统计留存 14 个月。

## 二、一条主线理解 ACD：六场景

每一通来电，引擎先看"开门了吗"，OPEN 后按资源占用落进六个场景，**每个场景的出口都独立可配**：

1. **有空闲坐席**：欢迎语 → 转坐席。
2. **坐席全忙**：进队列；先播消息 1，到阈值插播预计等待或排名，循环播消息 2；来电者随时按 `*` 自救（转组邮箱或指定号码）。
3. **队列满**：劝漏第一形态——转指定号码 / 进组邮箱 / 播劝漏语音后释放，按此优先级判定。
4. **ACD 端口全忙**（≤16，与 MLAA 共享）：跳过队列直接劝漏（第二形态），出口同上。
5. **全员登出/off duty**：**只有第一通**转预定义 Transfer number，后续要么排队要么劝漏——"来电时好时坏"的常见真相。
6. **组关闭**：关闭语后释放，出口同样三选。

排障口诀：任何"来电行为怪"先归场景，再核对该场景的出口配置。

## 三、配置的两层结构

**第一层 ACD Setup 向导**一次成型，页签按顺序做：

1. General：端口数、状态前缀 501 在值/502 离值/503 文书/504 暂离、组-DDI 关联
2. ACD Group：组邮箱
3. Profiles：坐席/班长按键模板
4. Agents/Supervisors：套模板到话机
5. OK 后**必须重启 ACD 引擎**——不重启不生效，这是新手第一大坑

向导会在后台自动生成虚拟终端、cyclic 寻线组、邮箱呼转、DDI、profiles——这些"自动生成物"别手改；同时有一个必须人工核对的开关：signalization mode 保持禁用，否则来话显示在组监管键上坐席没法接。

**第二层 ACD Services 菜单**做精细化：Line parameters（路由表）、Agent parameters（坐席入组与 rank）、General parameters（时段/队列/搜索模式/组名）、Voice messages（语音）。

## 四、四个"规则武器"

1. **呼叫特征化路由**：CLI 从左向右比、DDI 从右向左比；三级优先（双匹配 > 仅 DDI > 仅 CLI）；路由表**从最特殊填到最一般**，兜底条目必须显式写（没匹配的来电是回振铃，不进 ACD）。
2. **队列公式**：长度 = ceil(在值坐席 N × 话务因子 K)，K∈0.1-9.9、上限 16；N 只数 On duty——坐席签出队列立即缩容。预计等待 = (队列数/在值坐席 + 1) × 平均通话时长，线性估算高峰低估，对外承诺留余量。
3. **搜索模式三选一**：Fixed 按 rank 硬优先 / Rotating 轮转 / Longest idle 谁闲谁接；与 rank（组内序）、Priority order（跨组序）三层正交。叠加"无应答自动移除"后，超时未接的坐席会被自动置 off duty——坐席"集体消失"的怪象源于此。
4. **坐席建链**：坐席名+坐席号+组+终端四要素建立关联才接活（free seating）。登录后默认状态看 **ACDAutoLog**（01 在值/00 离值）——"登录了却不接电话"先查它。话机 ACD 页签状态码：`组号:等待数`，`+`=队满，`-`=组关闭。

## 五、三个客户端 + 一个扩展

- **Supervisor 班长台**：实时看坐席/组、改坐席组与 rank、开关组。坐席的 On Duty 有八个子状态（待接/未应答/转接预留/振铃/通话/刚挂休整/外呼中/处理非 ACD 来话）——"显示忙却不接"对照子状态定位。密码用独立 ACD Admin，别把 installer 密码给客户。
- **Agent 席面**：PC 绑话机；来话显示主叫/被叫/组名/等待时长；支持通话打标（Types 码表）、客户库弹屏、实时个人统计。
- **Statistics**：S1=10s/S2=40s 两个等待阈值定义统计口径；组/坐席两维、图形/表格、自动打印；导出 binary（自用）或 CSV（外部 BI）。
- **Multi-Secretary**：多经理共享秘书团，复用 ACD 引擎——经理 DDI 当被叫特征、秘书全 rank 1、话机显示被叫（经理）姓名。十步配置**顺序敏感**，乱序返工。

## 六、交付清单思维（从书到现场）

标准交付顺序：OMC 安装首连（改默认密码！）→ IP 规划 → 基础 ACD 三步走（向导/Services/语音）→ 路由表 → 时段日历 → 三件套部署 → 实呼验证。两个贯穿始终的红线：**教材所有密码与网段是实验值**（pbxk1064/Acdc1064 上生产=裸奔）；**容量与安全规划在书外**（话务量建模、SBC/中继安全需另行设计）。
