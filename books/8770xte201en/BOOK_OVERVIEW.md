## 2. 解释 (Interpretive)

### 关键术语 (作者本人的用法)

| 术语 | 作者的定义 | 和常识用法的差异 |
|---|---|---|
| Accounting record / ticket | OXE 在呼叫结束时生成的话务票据，最多 47 个字段（ED5.2 格式），先存内存缓冲（≤500 条）再压缩进 TAX*****.DAT | 不是"发票"，是逐呼叫的原始话单；缓冲满或 90 分钟无新记录才落盘 |
| ACCOUNT.LIS | 记录 OXE 上已建计费文件清单的索引文件；8770 靠与自己的副本对比决定增量取回哪些文件 | 它是增量同步的"游标"，不是日志 |
| Detailed accounting | 五种计费方法之一：更新组织树 + 从 PCX 取回票据并按分机归位 | 书中默认推荐法；与"只更新组织树不取票""按节点聚合"等方法并列，每台 PCX 可各选一种 |
| Carrier（运营商） | 资费容器：Period > Calendar/Region/Tariff/Direction 四件套；分 Outgoing 直连运营商与 pulse 型（Service） | 不代表真实运营商合同，只是 8770 里的一套算钱规则；名字/符号（≤5 字母）全局唯一 |
| Calling/Called region | 主叫区域=PCX 或 PCX-中继组所在计费区；被叫区域=同资费的被叫号码前缀集合；一个区域可兼两者 | 前缀按"最长最优匹配"归属；同一前缀不能出现在不同区域 |
| Direction | 主叫区域→被叫区域的配对，唯一绑定一个通信资费（可选服务资费/调整/时延） | 是算钱的最终落点；未定义的呼叫落"unspecified"方向兜底 |
| Tariff（资费） | 计算 mode：exact duration（线性，可带 initial cost/duration、minimum cost、segments）、round up/down、based on unit（脉冲）、PCX 给定成本 | 与"话费套餐"不同：它是一台服务器内可复算的确定性公式 |
| Cost center（成本中心） | OXE 侧为用户/话务台/数据终端指定的记账单位（默认 255 个槽位，255=未指定）；trunk group 等无成本中心对象落"默认成本中心" | 组织树的叶子主要是成本中心；在组织图上移动用户会被拒绝，必须回 OXE 配置改 |
| Organization tree | 财务组织的图形化树（level/cost center/用户），保留历史（灰色条目），随同步与事件自动更新 | 它存"过去"而不只是现状——同一分机的改 名/换成本中心都留痕 |
| Mask profile | 按呼叫类别（个人/项目/职业/访客）控制被叫号、主叫号、PIN、成本、地名、时长、日期的遮蔽位数；随组织树继承 | 遮的是"报告与记录查看"的显示，不是删数据；grouped report 只认 Default 档案 |
| Accounting domain（可见域） | 挂在组织树节点上的域名，分配给管理员后只看到域内数据；AdminNmc 看全部 | 群组上配域无效，只认用户级；启用后未配域时整树只剩根 |
| Cost profile（成本档案） | 对总成本做线性/百分比调整得到"发票价"；另含按呼叫类型、设备类型、月/周/日的订阅费 | 两套配置：Invoiced cost（每通话调价）与 Subscription（按期计费，每月 1 日出票） |
| Code book | 运营商配置的文本文件集（.inf/.rgn/.trf/.dir/.cal/.ccn/.adj/.fct/.itl/.trg），@表头、Tab 分隔、%注释 | 跨服务器迁移/存档运营商配置的载体；.itl 的 Node 必须与目标机声明名一致 |
| Report definition / Generated report | 报表定义（Querytool 选数据 + Designer 排版）与其实例；Detailed 不汇总、Grouped 汇总；Hit-list 限量 | 预定义报表必须复制到个人目录才能生成； cumulative report 依赖夜间算好的累计计数器 |
| Tracking profile | 阈值集合档案，可挂组织条目或运营商；超阈值出告警和/或发邮件；支持变化率（移动平均） | 阈值不是实时流式监控——靠每天的任务与夜间计数器驱动 |
| IP ticket / VoIP KPI | OXE 对每段 IP 通话出 SIP/IP 票据，含时延表、丢包、BFI 密度；KPI 阈值默认时延>150ms、丢包>3%、BFI burst>5% | 质量是按 10 秒段统计的，MOS 图要用散点图才可读 |
| pmm 文件 | OXE 每半小时生成的话务观察计数器文件（C<周><日><半小时><序号>.pmm），存在 /usr4/pmm | 流量分析专属（仅 OXE 支持）；与 TAX 票据同走一次同步回收 |
| archZ | 计费票据归档文件（zip 格式），每天每节点一个；Archive delay 31 天 + Clean-up delay 94 天，最长保留 125 天 | 按记录日期而非文件创建日期清理；恢复可打 Archived 标签与原数据区分 |

### 核心命题 (用自己的话)

1. 计费数据链是一条单向管道：OXE 内存缓冲（≤500 条，满或 90 分钟无新票落盘）→ TAX*****.DAT + ACCOUNT.LIS → 8770 对比索引经 FTP 增量取回到 loader 目录 → 加载过滤（时长/成本/呼叫类型/节点）→ MariaDB → 报表。哪个环节断了，按目录和日志（NMCLD_1.log 等）逐段查。
2. 8770 是"集中管理面"：IP 连通即可纳管 OXE（csa/csm 双地址）、OXO Connect（经 OMC）与 OpenTouch；thick client 五套件 + WBM 四应用 + Manage My Phone 分工明确，审计与流量分析仅支持 OXE。
3. 资费模型 = Region（主叫/被叫）× Direction（配对）→ Tariff；成本在票据加载时就算好，运营商配置改动后必须跑 Compute cost（Force）重算存量，否则新旧成本混存。
4. 费率公式可精确复算：exact 模式 Cost = 单元数×单价（按秒折算），可叠加接通费（initial cost）、免费时长（initial duration）、保底（minimum cost）、分段（segments）；round up/down 按阶段计；pulse 模式直接用票据里的 Charge units 乘单价。
5. 服务费独立建模：SVA 特服号（法国 08xx/短号）的通信费 C 与服务费 S 分开配资费，在 Direction 上叠加；总票价 = C + S。
6. 组织树决定"钱归谁"：成本中心从 OXE 同步（未设 cc=255 落根，中继组等落默认成本中心）；组织图上"剪贴=丢历史移动、复制=带历史另立（原条目转灰）"，用户只能在 OXE 配置/目录应用里改成本中心；误迁历史可用"设备级回溯创建日期"救回，level/成本中心/人不能回溯。
7. 机密性三道闸：mask profile 按组织树继承遮显示 → 解密需要"Mask data access"组成员口令 → accounting domain 按管理员裁剪可见范围；OXE 侧已遮蔽的号码（如 029845----）8770 无法还原。
8. 报表引擎两个页签分工：Querytool 管字段/排序/过滤/公式/hit-list（可设生成期过滤器），Designer 管版面/前缀后缀/小数位/图表；不同区域的表头不能混用出图；grouped 报表必须会嵌套 Sum 才能做出"按分机汇总再按成本中心汇总"。
9. VoIP 质量有量化口径：每段通话出 IP ticket（压缩算法、收发包、时延表、BFI 密度），默认阈值时延>150ms、丢包>3%、BFI burst>5%（且 BFI>3% 才算 burst）；清库周期小时/天/月/年计数器与票据各有一套。
10. 流量分析靠 OXE 半小时计数器（pmm/inf + pmm.lis），与计费票据同走同步；默认只算话务台/中继组，要看被叫号与终端必须把每日/每周任务的 -PtpType 参数改成 ALL。
11. Tracking 把阈值变成档案复用：变化率 = 100×(当前值−x 期均值)/x 期均值（日 30/月 3/年 1 期默认，可改），超限动作出告警、发邮件或两者；一封邮件可携带多个超限，附件按 profile 分类。
12. Web Performance 是 WBM 侧的实时仪表盘：VoIP CDR（SSH/FTP 取回）+ OXE SNMP MIB（A4400-RTM-MIB + UC-DAVIS，SNMPv3）两条数据腿，五大主题 widget，轮询 30 分钟可缩到 5 分钟；SNMP 配置不一致时 8770 出告警并停用监控。
13. 归档是数据生命周期的延长线：31 天后归档成 archZ（每天每节点一档），再 94 天后删，最长 125 天；恢复时可打 Loaded/Archived 标签，Archived 标签的票在组织树不可见但可出报告，并可"只清除恢复票"。

### 论证链

## 3. 批判 (Critical) ★

### 作者的时代局限
- 基于 R5.2 / Ed45 界面与 R101.1 实验机；8770 界面、预定义报表清单、WBM widget 随版本漂移。
- 虚拟化清单（ESXi 6.x/7.0/8.0、Hyper-V 2016/2019/2022、Nutanix AHV 20220304、AWS）与容量规划工具 V3.0 是 Ed45 时点口径，落地质询需重新核对支持矩阵。
- 费率示例停留在"分钟单价+固定税"的简化世界，未涉及融合套餐、流量计费、云话费分摊等现代形态。

### 作者的立场盲点
- 全书明文密码贯穿（Superuser2580*、superuser、Superuser01*、letacla1、pwdagentV3）；生产侧的密钥/口令治理只有一句"改成与 OXE 一致"，SNMPv3 认证/加密口令管理无展开。
- 运营商资费数据从哪来（真实价目表、监管费率文件）全书不谈——只教"怎么把资费敲进系统"，不教"资费数据工程"。
- 书内存在多处未修订的笔误：p402 与 p550 的同一练习汇率一个写 1€=1.21$ 一个写 1.3$；p607 练习写 "Telecom 1 or Telecom 7"、"Telecom 0/Telecom 7" 而 p613 过滤器实为 Telecom 1+Telecom 2；p89 表格把 31011 的姓/名写反（Adams Alice vs Alice Adams）。照抄实验值会踩坑。
- 数据库运维（MariaDB 容量、性能、备份策略）只在 Maintenance 应用一句带过，计费高峰的加载速度（实验口径 52 tic/sec）无生产容量结论。

### 未被证明的假设
- 假设读者已具备 OXE 维护基础：siteid、netadmin -m、account compress、accview、ipview、rstcpl 等命令只演示语法不解释体系。
- 假设单节点 OXE + 单 8770 即可代表生产：多节点（13101/13102 例）、PCS、OpenTouch 关联同步只有概念图，无实验。
- 假设币种/税率按国家安装时一次定死即可接受；跨国多币种场景只有"附加币种+汇率有效期"的机制，无实践指引。

### 最强反对意见
"这本教材教的是单节点实验闭环，不是生产计费系统实施"——真实运营商价目接入、多 PCX 组网、数据库容量与备份、安全基线（口令/SNMP 密钥/域控）、以及话费合规（GDPR 类留存期限）都只是指针或缺失。因此每条能力的 Boundary 必须标注"实验口径"，生产化须补：资费数据源管理、OXE 安全加固文档、8770 安装与容量规划指南三块外部输入。
