# 交付前数据采集（安装输入清单）

## R — 原文依据

> "Data collection gathers customer needs, information on its ecosystem and the functionalities to be implemented."（p43）
> "Ecosystem • OXO Connect Evolution: • Eth0: 192.168.1.246 • Eth1: 192.168.94.246 • PC: 192.168.1.10 • DNS: 192.168.1.250 • DHCP phones/xBS: 192.168.1.10 to 69 • Default router address: 192.168.1.254"（p44）
> "Outgoing calls • Users can dial 9 to exit • 1 user will not be authorized • International calls and special numbers will not be allowed"（p49）

出处：OXOCXTE300EN p43-49（采集讲义七页，全部为实验口径样例值）。

## I — 自述

交付从数据采集开始：先把客户输入定死，再动配置。清单七块：

- **生态 IP 规划**：OXO Eth0/Eth1、管理 PC、DNS、话机与基站 DHCP 池、默认网关
- **FTR 三参考值与终端清单**：Partner fleet / Sub-fleet / Installation reference；IP 话机、DECT 基站与手柄数量
- **七个系统账户密码表**：Attendant / Administrator / Installer / Download / NMC / ACD / Users，逐客户必不同
- **编号计划**：内部分机段、话务台号、主中继组号、hunt group 段、DDI 段与 Base 映射
- **语音信箱要求**：信箱模式（Standard/Guest/Answer-only）、是否录音监听、建删需求
- **组与可编程键**：hunt/代接/广播/经理-秘书组的成员与权限、每话机按键需求
- **呼入呼出与运维前提**：话务台组与时段、欢迎/预公告、SIP 参数、出局限制（谁可外呼/国际与特服）、Rainbow 前提（公司与管理员已定）、备份周期与升级计划

## A1 — 书中案例

**采集样例（p43-49，实验口径）**：

1. 生态：Eth0 192.168.1.246、Eth1 192.168.94.246、PC 192.168.1.10、网关 .254、DNS .250、DHCP 池 .10-.69
2. 终端：4 台 IP 话机、1 台 xBS 基站、1 支 DECT 手柄（实验口径）
3. 密码表：七账户逐一定义（如 Installer=Alcatel1、Attendant=Letacla1，实验口径）
4. 编号：三位计划——分机 100-199、话务台 0、主中继组 0、hunt 500-525、DDI 41100-41199
5. 信箱：1 个 answer-only、1 个可录音带实时监听、按需建删
6. 组：hunt 501 含 3 话机、代接组 3 话机、广播组 1 发 2 收、经理-秘书组一对
7. 呼入：2 个话务台组+默认组 8，时段 8-19 组 1、19-8 组 2，欢迎预公告
8. 呼出：拨 9 出局、1 用户无外呼权、国际与特服禁、部分用户须经话务台
9. Rainbow：将接 Rainbow 含网关，公司已建、管理员已定
10. 维护：1 个自动周期备份、版本升级计划

## A2 — 未来触发

使用情境：新项目开工前的输入表；客户需求调研纪要转安装数据；投标澄清编号与权限口径；换经销商接手存量系统补档案。

语言信号：数据采集 / data collection / 安装前准备 / IP 规划 / 编号计划 / 密码表 / 需求清单 / 呼入呼出需求。

与相邻能力区分：清单定稿后的系统开通 → 开通能力；编号段的具体落库 → 编号计划与组能力。本能力到"客户安装数据表成文"为止。

## E — 可执行步骤

输入契约：客户需求调研纪要、现有网段与号码资源、运营商参数（生产）。客户需求未澄清 → 判停先补调研（调研方法论在书外）。

1. 填生态 IP 表：OXO 两口/PC/DNS/DHCP 池/网关。完成标准：无地址冲突且与客户网段协调
2. 填三参考值与终端清单。完成标准：FTR/向导可直接照抄
3. 定七账户密码：每客户唯一、管理密码 8 位含大小写与数字。完成标准：密码表成文且不入明文流转
4. 定编号计划：分机段/话务台/主中继组/hunt 段/DDI 与 Base。完成标准：无段冲突、预留扩展空间
5. 定组与按键：四类组成员、权限、话机键位。完成标准：与客户业务对得上
6. 定呼入呼出：话务台组与时段、预公告、出局权限矩阵。完成标准：业务口径书面确认
7. 登记运维与云前提：备份周期、升级计划、Rainbow 公司与订阅状态。完成标准：交付检查表闭环

判停点：

- 客户对编号/权限口径未确认 → 不进入配置，避免整库返工
- 运营商 SIP 参数未到手 → SIP 网关章不排期
- Rainbow 公司未由 BP 建 → 接入章挂起（权责在 BP 侧）

输出契约：客户安装数据表（七块齐备）+ 密码管理口径（脱敏流转）。

## B — 边界

- 本卡全部样例值（IP/密码/号码）为实验口径，生产按客户真实数据整体替换
- 真实客户需求调研方法论在书外；书内只给"采什么"不给"怎么谈"
- 安装号与话务员 DDI 的实验值在书内存在两处口径（见 needs-review nr-02），引用时按所在章节并标注实验口径
- 密码表属敏感信息：交付文档中只留占位与负责人，不留明文（原书样例明文印刷，不得照搬）
