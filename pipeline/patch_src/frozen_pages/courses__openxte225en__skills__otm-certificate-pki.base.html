I — 自述

证书是远程访问的硬前提，三件事先分清：

  1. 三来源选型：CA 服务器签发（远程访问必需、安全性最佳）、自签（有安全弱点）、预载"通用证书"+CTL（安装时选、安全关闭）——官方明确反对最后一种：话费欺诈与服务盗用的风险都会上升；结论口径是用外部 PKI 取得 CA 根证书
  2. 两封装规则：CSR 在申请方服务器上生成，CA 只发证书链，用 PKCS7；密钥对在 CA 侧生成，打包带 passphrase，用 PKCS12。封装由"私钥在哪生成"决定，选错导入流程就走不通
  3. 远程访问两种布局（p58-59）：
布局 证书张数 SAN 要求
案例 1 通配符 一张 *.域名 部署到 OpenTouch/RP/OTSBC 三处 会议 FQDN 仍须在 SAN 覆盖范围
案例 2 每服务器专用 OT/边缘各一张 OT 证书 SAN 含 opentouch+conference；边缘证书 SAN 含 public-ot+conference

部署五步清单（p54-55/p60/p76）：

  1. 生成 CSR（WebAdmin 里做会同时生成密钥对；也可直接在 CA 服务器做）
  2. CA 签发证书
  3. CA 根证书导入各客户端与 OpenTouch/边缘服务器（建立信任）
  4. 导入服务器证书（PKCS7 或带 passphrase 的 PKCS12）
  5. 点 Deploy 部署生效——不点不生效

联动规则：服务器证书变更后，话机使用的 CTL 必须重新生成（重新签名）——操作在另一培训规程（p268/n05）。

A1 — 书中案例

OpenSSL 自建 CA 并签发通配符证书（p260-268，实验口径环境值见 book/overview）：

  1. 在 CentOS 服务器建 /CA/authority、/CA/certs、/CA/keys 三个目录
  2. openssl genrsa -out rootCA.key 2048 生成根 CA 私钥
  3. openssl req -x509 -new -nodes -key rootCA.key -days 3650 -out rootCA.pem 自签根证书
  4. openssl genrsa -out servers.key 2048 与 openssl req -new 生成服务器密钥与 CSR（CN 填通配符域名）
  5. openssl x509 -req -in servers.csr -CA rootCA.pem -CAkey rootCA.key -CAcreateserial -out servers.crt -days 3650 签发
  6. openssl pkcs12 -export 打包 servers.p12（导出口令即生成时的挑战口令）
  7. 浏览器把 rootCA.pem 导入受信任的根证书颁发机构（Windows 级生效，Chrome/IE/Edge 都要）
  8. WebAdmin，Change server certificate 选 External certificate (import pkcs#12 file)，填 passphrase 导入

验证：p263 签发输出 "Signature ok" 与 subject 行；导入后 https 会话被切断属预期（见 B）。

A2 — 未来触发

使用情境：上远程接入前定证书方案；"装的时候图省事选了通用证书"的存量系统整改；自建 CA 或向客户 PKI 提交 CSR；会议邀请链接打不开查证书；换证书后话机异常。

语言信号：证书 / certificate / CA / 自签 / self-signed / 通用证书 / generic / PKCS7 / PKCS12 / CSR / SAN / 通配符 / wildcard / 根证书 / CTL / Deploy。

与相邻能力区分：

  • 证书就绪后的服务器侧申报 → OT 服务器侧设置能力
  • OTSBC 侧证书导入动作 → OTSBC 部署能力
  • Nginx 侧证书落位 → 反向代理能力

E — 可执行步骤

输入契约：域名规划（公共 FQDN 清单，必含会议服务 FQDN）、CA 可用性（客户 PKI 或自建）、各服务器管理入口。

  1. 选布局：多服务器同域且允许通配符 → 案例 1；合规要求专用证书 → 案例 2。完成标准：证书清单列出每台服务器的证书形态
  2. 按 p61 红线排除"通用证书"方案；自签仅限纯内网，远程接入一律 CA 签发。完成标准：选型结论有依据页码
  3. 生成 CSR 并记录封装路线：本机生成走 PKCS7、CA 侧生成走 PKCS12。完成标准：CSR 与私钥保管位置明确
  4. CA 签发（Windows CA 用 Web Server 模板 base-64 提交，或按 A1 OpenSSL 流程）。完成标准：拿到证书或证书链文件
  5. 根证书分发到客户端与 OT/边缘服务器。完成标准：浏览器与服务器都信任该 CA
  6. 各服务器导入证书并点 Deploy。完成标准：WebAdmin 证书页显示新证书且已部署
  7. 核验 SAN：证书 Details 页查看 Subject Alternative Name 含会议 FQDN。完成标准：会议邀请域名在 SAN 列表内

判停点：

  • Deploy 后弹"Impossible to retrieve data"且 WebAdmin 掉线 → 不是故障，重开会话即可（n04）
  • 换证书后话机异常 → 先想到 CTL 未重签；该操作书外（n05），声明边界后转对应规程
  • 客户 PKI 要求专用模板/密钥托管 → 停，正式 PKI 流程与通配符合规性在书外，按客户安全规范走

输出契约：可用的服务器证书（SAN 核验通过）+ 已分发的 CA 根证书 + CTL 重签待办移交项。

B — 边界

  • 预载"通用证书"+CTL（security off）被官方明确反对——存量系统先补证书再谈远程接入（p61/n01）
  • 正式环境的证书申请流程、通配符证书的合规性原书未讨论；实验用自建 Windows CA 与 OpenSSL CA 两条路径，均为实验口径
  • 服务器证书变更后 CTL 重签在"另一培训规程"，本书不含（p268/n05）
  • 会议 FQDN 进 SAN 的强制警告针对 RP 与 OT 服务器两类证书；OTSBC 证书复用时也要补 OT/会议公共名（p135 Notes）
  • 本卡不涉及具体 IP/口令等环境值，实验签发环境见 book/overview 环境区
