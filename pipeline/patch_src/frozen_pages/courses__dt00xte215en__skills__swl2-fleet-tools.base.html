I — 自述

两个"看与装"的工具域：Fleet Supervision 看资产合规（云、免费、只读），OST 装机与排障（桌面工具）。

  1. Fleet Supervision 四块能力（p558-560）：软件版本可视、库存可视化（机箱/电源/光模块/AP 钻取）、KPI 仪表盘（生命周期 GA/EoS/EoL、维保 Active/Expired/None）、资产汇聚；免费但只读——配置管理仍在 OmniVista/CLI
  2. Fleet 开通三路（p563）：声明 OV 2500（取 OV2500 ID）、OV Cirrus 4.X（URL+API Key）或 Cirrus 10.5+（URL+Organization ID+App ID/Secret）；无 OmniVista 时 CSV/XLSX 模板导入
  3. OST 功能五块（p217-223）：装机与排障（快速识别接入设备）、PoE 向导（逐设备验证/一键修复不启动的 PoE 设备/查剩余预算）、快捷工具（Reset Port/Cable Test/ping）、Auto-Ticket（收集 TAC 材料生成工单模板）、流量分析（坏线/SFP、丢包、广播风暴）；另有 Config 向导与备份恢复（RMA 换机还原）
  4. OST 两代边界（p224-230）：1.0=单机社区版（GitHub/Spacewalkers，ALE 停止开发）；2.0=Client-Server+PostgresSQL，容量 100 交换机/4000 设备/5 并发客户端，数据库静态加密；MyPortal 免费下载但需有效 OmniSwitch 支持合同（BP 需分销协议）
  5. OST 2.0 安装链（p573-580）：Windows 10/11 + Postgres（测试版本 18.1，先装、设库密码、不装 Stack Builder）> Server（与 Postgres 同机）> Server Configuration Tool 初始化（填 Postgres 密码测连接、定 OST admin 密码）> Client 连接后添加交换机

A1 — 书中案例

OST 2.0 安装实验（p572-580，How-To）：

  1. 前置：Windows 10/11，从 postgresql.org/download 取 Windows x86-64 版（测试版本 18.1）
  2. 装 Postgres：运行 postgresql-18.1-2-windows-x64.exe，设数据库访问密码、保留默认端口、取消 Stack Builder
  3. 装 OST 2.0：Server（必须装在 Postgres 所在服务器）+ Client（默认同机）
  4. 初始化：运行 OmniVistaSmartTool.ServerConfig.exe（C:\Program Files\Alcatel-Lucent Enterprise\Tools 下），填 Postgres 密码并测试连接
  5. 定义 OST admin 密码，完成 Server 配置
  6. Client 连接 Server，登录成功
  7. Client 内 Add a switch 纳管第一台交换机

Fleet Supervision 章为控制台操作截图讲义（p555-569），无实验与警示框——开通动作按上面 I 段第 2 条三路执行。

A2 — 未来触发

使用情境：全网资产与维保到期报表；软件版本合规盘点；没有 OmniVista 怎么进 Fleet；装机排障提效；PoE 设备不启动一键修复；OST 装不上/连不上。

语言信号：Fleet Supervision / Services Kiosk / myfleet / 资产 / 维保 / EoL / 合规 / OST / OmniVista Smart Tool / PoE 向导 / Auto-Ticket / Postgres / Server Configuration / 一键修复 / 支持合同。

与相邻能力区分：

  • PoE 交换机侧配置（预算/优先级/Fast PoE）：LLDP 与 PoE 能力卡
  • 命令行排障八件套：诊断工具箱能力卡
  • 升级本身（版本/通道/RMA 风险）：升级与 Auto-Fabric 能力卡

E — 可执行步骤

输入契约：资产来源（OV 2500/Cirrus 版本或设备清单文件）、OST 使用者数与规模（100 交换机/4000 设备/5 并发内）、支持合同状态、Windows 服务器。合同未核实 → 判停先查。

  1. 合同核查：OST 2.0 需有效 OmniSwitch 支持合同（BP 需分销协议）；Fleet 免费无合同门槛。完成标准：获取路径明确
  2. Fleet 开通：myfleet.ovcirrus.com 注册 > 按来源三路声明（OV 2500/Cirrus 4.X/Cirrus 10.5+）或模板导入。完成标准：资产看板出数
  3. 合规盘点：看生命周期 KPI（GA/EoS/EoL）与维保状态（Active/Expired/None），对无支持/将到期设备走 Services Kiosk 申请续保。完成标准：报表可交付
  4. OST 前置：Windows 10/11 + Postgres 18.1 先装（设库密码、默认端口、不装 Stack Builder）。完成标准：数据库就绪
  5. OST 安装与初始化：Server 与 Postgres 同机安装 > ServerConfig 填库密码测连接 > 定 OST admin 密码。完成标准：连接测试通过
  6. 纳管与使用：Client 连 Server > Add a switch > 按需用 PoE 向导/快捷工具/流量分析。完成标准：第一台交换机数据可见

判停点：

  • 拿不到 MyPortal 下载权限或无支持合同 → 停，1.0 社区版无新特性修复，把理顺合同作为前置任务
  • 想在 Fleet 上改配置 → 只读监管，配置管理回 OmniVista/CLI
  • 超容量（>100 交换机/>5 并发） → 2.0 口径之外，找 ALE 确认扩展方案
  • Postgres 后装 → 顺序错误，卸载重来（Server 必须与 Postgres 同机）
  • 要用 OST 1.0 的既有习惯 → 1.0 已停更，规划迁移到 2.0 的 Client-Server 形态

输出契约：可用的资产合规看板（Fleet）或可用的 OST 2.0（Server+Client+首台纳管），及合同/容量边界说明。

B — 边界

  • Fleet Supervision 免费但只"看"不"管"（p556-558）；原书该章无警示框，边界如实留白
  • OST 2.0 容量与并发（100/4000/5）为 2.0 口径（p225）；数据库静态加密随包提供
  • OST 支持条件与 OmniSwitch 支持协议绑定（p229）；Postgres 密码即 ServerConfig 时所填，丢了按数据库侧找回（书外）
  • OST 1.0 下载源（Spacewalkers/GitHub）仅为存量资产，不再新增能力（p230）
  • 环境类地址与账号（R-Lab 服务器等）见 book/overview 环境区，不进本卡
  • OmniVista 平台自身的部署与策略下发（PolicyView）不在本书范围
